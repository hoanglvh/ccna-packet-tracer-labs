## Capstone Challenge
1. ```
   ipv6 unicast-routing
   ipv6 dhcp pool USERS-V6
    dns-server 2001:db8:acad:10::53
    domain-name ccna-lab.com
   interface g0/0/1.10
    ipv6 address 2001:db8:acad:10::1/64
    ipv6 address fe80::1 link-local
    ipv6 nd other-config-flag
    ipv6 dhcp server USERS-V6
   ```
   PCs: IPv6 Configuration → Automatic. They build their address with SLAAC and get the DNS server from stateless DHCPv6.
2. ISP: `ntp master 3` (Packet Tracer: or use a server's NTP service). R1: `ntp server 209.165.200.225`, `service timestamps log datetime msec`, `logging host 192.168.30.10`. Note that the SERVER-PROTECT ACL does not block syslog because the messages are generated by R1 itself.
3. `ip access-list standard NAT-INSIDE` → `permit 192.168.10.0 0.0.0.255`, `permit 192.168.20.0 0.0.0.255`; `no ip nat inside source list 1 interface g0/0/0 overload`; `ip nat inside source list NAT-INSIDE interface g0/0/0 overload`. NAT only uses the ACL to **select** which inside source addresses are translated – the type of ACL (numbered or named standard) doesn't matter. (You may need `clear ip nat translation *` before changing the NAT statement.)

## Review Questions
1. **Discover** – client → broadcast; **Offer** – server → client (unicast or broadcast depending on the client's broadcast flag); **Request** – client → broadcast (so other servers learn their offer was declined); **Acknowledge** – server → client (unicast or broadcast).
2. Routers don't forward broadcasts, so a client's DHCP Discover never reaches a server on another subnet. `ip helper-address` on the interface **facing the clients** (G0/0/1.20) converts the broadcast to a unicast toward the server and sets giaddr.
3. Rogue DHCP servers (MITM / DoS by wrong gateway/DNS) and DHCP starvation (with rate limiting). Only ports toward legitimate DHCP servers or relay agents (uplinks) are trusted.
4. Example `tcp 209.165.200.226:1025 192.168.10.11:1025 203.0.113.10:80 203.0.113.10:80`: inside local = 192.168.10.11 (PC's private address), inside global = 209.165.200.226 (public address representing it), outside local and outside global = 203.0.113.10 (the web server as seen from inside and outside – identical because we don't translate outside addresses).
5. PAT lets thousands of inside hosts share a single public IPv4 address (using port numbers), while dynamic NAT needs one public address per simultaneous host – public IPv4 addresses are scarce and expensive.
6. Standard ACLs filter on source only, so placing them close to the source could block that source from every destination – place them close to the **destination**. Extended ACLs are specific (source, destination, protocol, ports), so place them close to the **source** to drop unwanted traffic early and save bandwidth.
7. DHCP Discover/Request packets have source IP 0.0.0.0 and destination 255.255.255.255, so they would match neither the guest-subnet permits nor the deny line, and would be dropped by the implicit deny. Without DHCP, guests get no address.
8. `ip access-group` applies an ACL to traffic passing through an **interface** (in/out). `access-class` applies an ACL to **VTY lines**, controlling who can open (in) or initiate (out) Telnet/SSH management sessions.
